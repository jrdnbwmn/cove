## Tasks

### Task 1 [Master]: Add and register the generic Loops delivery method

**Skills:** loops-api, write-tests
**Reference:** Read [`app/clients/loops_client.rb`](../../app/clients/loops_client.rb),
[`test/clients/loops_client_test.rb`](../../test/clients/loops_client_test.rb), and
[`docs/designs/cov-37-loops-architecture.md`](../designs/cov-37-loops-architecture.md)
for the HTTP client, idempotency, and header-transport contracts.

**In scope:**

- Add `LoopsDelivery` as an Action Mailer delivery method.
- Register it as `:loops`.
- Read `X-Loops-Transactional-Id` and JSON-encoded
  `X-Loops-Data-Variables`.
- Issue one `LoopsClient` transactional send per message recipient.
- Fail loudly for missing headers, malformed JSON, or a variables value that is
  not an object.
- Preserve the stable idempotency header generated by `LoopsClient`.
- Allow Loops and network exceptions to propagate unchanged.

**NOT in scope:**

- No Devise mailer, template IDs, environment selection, retry changes,
  background delivery, attachments, contact creation, or edits to `LoopsClient`.
- No silent fallback to SMTP or another delivery provider.
- No edits under `lib/jumpstart/`.

**Build order:**

1. **Test:** Create `test/mailers/loops_delivery_test.rb` first. Using real
   `Mail::Message` objects and WebMock at the Loops HTTP boundary, prove:
   - Valid headers produce exactly one authorized transactional request per
     recipient.
   - The request contains the expected transactional ID and decoded data
     variables.
   - Its `Idempotency-Key` matches `LoopsClient#idempotency_key`.
   - Missing headers, invalid JSON, and non-object JSON fail before any request.
   - `LoopsClient::RateLimit` and `LoopsClient::UnprocessableContent` propagate.
   - Boot registration maps `:loops` to `LoopsDelivery`.
   Run the test and confirm it fails before implementation.
2. **Implement:** Add `app/mailers/loops_delivery.rb` with the Mail
   delivery-method constructor and `deliver!` contract. Add
   `config/initializers/action_mailer.rb` to register it through
   `ActionMailer::Base.add_delivery_method`.
3. **Verify:**
   `mise exec -- bin/rails test test/mailers/loops_delivery_test.rb`

### Task 2 [subagent]: Build the bodyless Devise mailer and template configuration

**Skills:** loops-api, write-tests
**Reference:** Read [`app/mailers/application_mailer.rb`](../../app/mailers/application_mailer.rb),
[`config/initializers/devise.rb`](../../config/initializers/devise.rb),
[`config/routes/users.rb`](../../config/routes/users.rb), and the inactive
templates under `lib/jumpstart/app/views/devise/mailer/`.

**In scope:**

- Add the checked-in transactional IDs under `shared.transactional` in
  `config/loops.yml`.
- Add `LoopsDeviseMailer < Devise::Mailer`.
- Override only `reset_password_instructions` and `password_change`.
- Use Devise's existing mailer helpers so normal recipient and option handling
  remain intact.
- Attach the transactional ID and JSON data as the two internal Loops headers.
- Build the reset URL with the real `edit_password_url` helper and Devise's raw
  token.
- Pass `body: ""` so template discovery and ERB rendering never run.
- Add an `# AIDEV-NOTE:` documenting that Loops owns the body and subject while
  vendored views remain intentionally unreachable.
- Use strict configuration lookup so missing notification mappings fail loudly.

**NOT in scope:**

- No Devise initializer wiring yet.
- No confirmation, unlock, email-change, AccountMailer, or Pay mail actions.
- No email copy, subjects, layouts, previews, new views, credentials, or edits
  under `lib/jumpstart/`.
- No change from synchronous `deliver_now`.

**Build order:**

1. **Test:** Create `test/mailers/loops_devise_mailer_test.rb` first. Prove:
   - Reset instructions use `cmsdnzduk02k40jx72rv3uwe2`.
   - Reset variables contain exactly `recipient_email` and
     `reset_password_url`.
   - The URL equals the real `edit_password_url` helper result, resolves to
     `Users::PasswordsController#edit`, and carries the raw token as
     `reset_password_token`.
   - Password change uses `cmsdo8ixv001e0j1zu027i3s7` and only
     `recipient_email`.
   - Both messages have empty, non-multipart bodies.
   - A test-only subclass whose renderer raises can still build both messages,
     proving no ERB rendering occurs.
   - `Rails.application.config_for(:loops)` exposes the exact checked-in
     mappings.
   Run the test and confirm it fails before implementation.
2. **Implement:** Add `config/loops.yml` and
   `app/mailers/loops_devise_mailer.rb`. Keep payload construction inside the
   mailer and delegate HTTP delivery to `LoopsDelivery`.
3. **Verify:**
   `mise exec -- bin/rails test test/mailers/loops_devise_mailer_test.rb`
4. **Review:** After Tasks 1-2 are both complete, run `review-changes-mini`
   exactly once for Checkpoint 1. If these tasks were executed in parallel, the
   Master runs the review after both return.

## Task Dependencies

- Tasks 1 and 2 are independent and can run in parallel: the delivery method
  consumes generic headers while the Devise mailer produces them.
- Task 3 depends on both Tasks 1 and 2 because its request-flow tests use the
  registered delivery method and bodyless mailer.
- Task 4 depends on Task 1 and follows Task 3 so production is not activated
  before the Devise path is complete.
- Task 5 depends on all implementation tasks.
- Task 2 is the only delegated task: its three-file scope is independent and
  unambiguous. Tasks 1, 3, 4, and 5 establish shared transport, authentication,
  environment, or review behavior and remain with the Master.
